# Travel periods and creation controls (2026-11-06)

New polls can use 하루 보기 (existing lunch/dinner voting) or 여행 가기. Travel creators enter a whole number of days (2–30), then choose the candidate search range with the existing month/date selector. Five days produces every overlapping five-day window inside that range, including windows spanning months/years. It does not skip otherwise valid start dates to create only disjoint blocks.

Travel participants mark whole days. Both existing L/D cells are saved together, so no DB rule change or new vote slot is needed. All days in a window must have explicit full-day positive responses to count a participant as available. Any impossible half-day makes the participant unavailable for that window; a missing day remains unanswered; any tentative choice makes an otherwise complete window tentative. Ranking keeps the existing unavailable-count, available-count, score, start-date order. Normal polls without meetingType keep their old behavior.

Trip confirmation stores date plus endDate, reserves both meal slots on every trip day for all participants, and uses source-scoped automatic X overlays in overlapping polls. Change/cancel restores manual choices; intersecting target ranges and other overlapping reservations are retained correctly. Existing single-slot reservations retain their old format. Confirmed trips are read-only until cancellation, like day polls. Manual cross-poll sticker importing is hidden for travel polls, to avoid treating partial-day availability as a full travel day.

The creation action is above the information inputs. Missing information focuses the corresponding input and shows guidance. Participant count defaults to 2 and supports minus/plus plus direct numeric typing (2–100). Existing count editing uses the same stepper in a dialog, with the current membership count as the lower bound. Non-creators can tap edit controls but see exactly `모임 정보는 모임장만 수정할 수 있어요`; server ownership checks still deny edits.

Validation: native mobile Chromium fixture covers form order, empty-submit focus/toast, count stepper and typing, travel mode, guest draft creation, whole-day vote storage, six five-day windows over ten available days, creator-only edit toasts, range ranking and confirmation UI. Node tests cover leap/year boundaries, tentative/missing/impossible aggregation, multi-day reservation overlap, full-range X propagation/cancellation and legacy day-poll regressions. Production release uses the staged read-only candidate gate before activation.

Confirmation entry was moved from the page top and individual row actions to the upper right of the first-ranked card. It arms selection, shows `아래에서 확정된 날짜를 눌러주세요`, and confirms the clicked ranked candidate directly, including the whole range for trips. Selection can be cancelled. Ownership and pending-save checks run before the server action; a source already committed remains displayed as confirmed while its durable X propagation finishes.

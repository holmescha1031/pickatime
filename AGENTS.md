# Project conventions and user preferences

- Keep existing polls and stored votes compatible. Use the staged release script; do not change DB rules during ordinary API requests or a routine UI release.
- Give content and action buttons deliberate spacing by default. Use the shared `dialog-stack` layout (24px gap) for new or updated stacked modal sections; do not rely on incidental paragraph/figure margins. Prevent duplicate CSS rules from silently cancelling spacing. Check rendered mobile spacing when changing dialogs.
- In the Korean product UI, write “구글” consistently, including “구글 캘린더 연결하기”. Keep actual API identifiers, domains, OAuth scopes, and English policy text intact.
- Connection dialogs show one explanatory/status message at a time. Once connection is attempted, hide the introductory account explanation and show the current progress/error instead.
- Render compact examples directly in HTML/CSS where practical, avoiding an extra screenshot download and keeping text sharp. Example content must be fictional and visually isolated from interactive voting controls.
- Place the meeting-date confirmation action outside the ranked date cards, right-aligned above the list; do not put it inside the first-ranked card.
- Keep the cross-poll import action as a compact pill on the left of the save-status row; keep the save status on the right. Show the drag hint below the sticker legend.
- On the signed-in home screen, use inline “모임 생성 / 모임 목록 보기” tabs; keep guest creation simple. Switching tabs or restoring a session must preserve in-progress inputs. List unconfirmed meetings by the displayed candidate date, then place confirmed meetings below them.
- Day/trip kind choices have no subtitles. Use the same editable number stepper for participant count and trip days, with space before the date-range section. Keep missing-field notices brief and specific.
- Put the participant-count editor in a small pencil icon beside the attendance count. Keep the lower bound at the current participant count (and the existing minimum of two); do not show the old count explanation or sticker-voter sentence. Use styled app dialogs for nickname changes.
- Keep sticker instructions in a compact card with tighter rows and a centered drag hint. The compact import pill uses the previous purple action palette, distinct from the green save status, with a small gap before the calendar. Match the sticky voting-tabs backdrop to the exact fixed page background.
- Use “스티커 모두 떼기” for the clear action.
- Place the home hero above the creation/list tabs and the creation action after all form fields. Keep the loaded meeting list when switching home tabs; refresh only on explicit refresh or a new home view/account. Parallelize independent reads and render existing votes before private-profile/join bookkeeping finishes.
- Month/date choices have no small subtitles. Default explicit start to local today and end to local today plus 14 days; preserve valid restored drafts. Use small food/palm icons for day/trip, centered rounded SVG stepper symbols, and a centered participant hint without the parenthetical minimum.
- Use 🍖 for the day-meeting icon and keep day/trip and month/date choices at the same compact 58px minimum height. Kakao ranking template 138674 uses actual current meeting title and availability thumbnails: all participants → yellow all-available badge; >=80% → sparkle eyes; >=50% → normal eyes; otherwise question eyes. Use the Kakao template’s built-in ranking numbers.
- Use the user-provided calendar-and-three-people logo for home and voting screens. Center the home hero logo; keep the voting logo in its existing left header position and width. Serve the physically trimmed optimized WebP; render it normally without positioned CSS cropping.
